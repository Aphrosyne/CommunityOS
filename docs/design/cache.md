# Cache Service 缓存服务

> **状态：** 正式
> **版本：** v1.0
> **最后更新：** 2026-07-02

---

# 目的

Cache Service 为 CommunityOS 提供统一的本地文件缓存能力。

当前版本主要服务于图片处理流水线，用于复用已经完成的解混淆结果，减少重复图片处理带来的 CPU、内存和临时文件开销。

缓存不是图片存储系统，也不依赖 QQ 消息历史记录。

当缓存不可用、缓存文件损坏或缓存读取失败时，图片处理流程必须自动回退到正常处理，不能因此导致功能不可用。

---

# 当前范围

当前 Cache Service 只缓存图片解混淆结果。

已覆盖的场景包括：

* 发布或混淆时，混淆完成后将原图写入缓存；
* 解图时查询缓存，命中则直接返回原图，跳过解码计算；
* 首次解混淆外部混淆图后，缓存结果供后续复用。

当前版本不缓存：

* QQ 消息对象、群聊历史记录；
* 用户会话状态、指令执行结果、权限判断结果；
* 图片下载 URL、发布消息本身。

---

# 设计原则

## 结果缓存

缓存的对象是已完成处理的图片文件。缓存命中后直接复用结果，不重复执行解混淆算法。

---

## 内容寻址

缓存键基于混淆图内容的 MD5 哈希生成。同一张图片即使来源不同，只要内容相同均可命中。

---

## 单方向缓存

当前仅缓存解混淆方向：`MD5(混淆图) → 原图`。混淆不单独缓存——混淆的一对一场景收益小，且解混淆端写入已覆盖。

---

## 缓存可失效

缓存仅是性能优化，不是业务正确性的唯一来源。缺失、损坏或读取失败时回退正常处理。

---

# 缓存目录

当前图片缓存目录为：

```text
data/
└── cache/
    └── images/
```

缓存文件不应放入：

* `logs/`；
* 临时目录；
* 用户上传目录；
* 项目源码目录；
* Git 版本控制目录。

`data/cache/` 应加入 `.gitignore`。

---

# 缓存键

图片缓存键为混淆图内容的 MD5 哈希，加 `.jpg` 后缀作为文件名：

```text
{md5_hex}.jpg
```

缓存键不包含用户 ID、群 ID、消息 ID、文件名、图片 URL 或发布目标群。

---

# 图片流水线集成

## 写入（publish / obfuscate）

混淆完成后调用 `cache_set(obfuscated_data, original_data)`，将原图写入缓存。

## 读取（decode）

解混淆前调用 `cache_get(obfuscated_data)` 查询缓存，命中则直接返回原图，跳过 `deobfuscate()`。未命中则正常执行解混淆，成功后调用 `cache_set(obfuscated_data, result)` 写入缓存供后续复用。

```text
接收混淆图
    ↓
计算 MD5
    ↓
查询缓存
    ├─ 命中：直接返回原图
    └─ 未命中：执行解混淆 → 写入缓存 → 返回结果
```

发布目标群不属于缓存键的一部分。每次发布仍独立发送群消息。

---

# 清理与淘汰

当前采用基于文件修改时间的最旧文件优先淘汰策略，总大小由 `IMAGE_CACHE_MAX_MB` 限制（默认 500MB）。

每次写入后检查总大小，超限时按 `mtime` 升序删除最旧文件。无 TTL 或定时清理——用户频繁重启 bot，定时机制收益有限。

---

# 日志

Cache Service 不单独创建日志文件。缓存事件由调用方写入对应业务日志。

图片缓存事件写入 `image.log`，包括：

* 缓存命中
* 缓存写入

普通缓存未命中不记录，避免日志噪音。缓存服务自身异常为 debug 级别，仅在调试模式可见。

格式示例：

```text
[缓存] 命中: a1b2c3d4.jpg
[缓存] 写入: e5f6g7h8.jpg
```

---

# 错误处理

缓存错误不得阻断图片主流程。

* 缓存读取失败 → 视为未命中，执行正常处理
* 缓存写入失败 → 正常返回本次处理结果
* 缓存淘汰失败 → 等待下次写入时自动重试

---

# 与其他服务的关系

## Logger Service

缓存服务自身的异常通过 Logger Service 以 debug 级别输出。

图片缓存命中、写入等业务事件由 `image_obfuscator.py` 中的 `cache_get` / `cache_set` 写入 `image.log`。

## Image Obfuscator Service

`image_obfuscator.py` 持有 `FileCache` 实例并暴露 `cache_get` / `cache_set` 函数。`obfuscate` / `deobfuscate` 不直接涉及缓存逻辑。

---

# 当前版本不包含

当前 Cache Service 不包含：

* Redis；
* 数据库缓存；
* 分布式缓存；
* QQ 消息历史复用；
* 图片 URL 下载前索引；
* 永久图片归档；
* 用户主动查看缓存；
* 用户主动删除缓存；
* 多实例缓存同步；
* 缓存配额管理；
* 缓存加密。

这些能力不属于当前阶段需求。

---

# 总结

Cache Service 通过缓存图片解混淆结果，减少重复解混淆的计算开销。

它以混淆图内容的 MD5 哈希作为缓存键，保证同一张混淆图无论来源均可命中。

缓存仅用于性能优化。任何缓存异常都必须回退到正常图片处理流程，保证 CommunityOS 的核心图片功能不依赖缓存可用性。
